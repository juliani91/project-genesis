Profiles

Documentation

How to use Project Genesis.

This public guide mirrors the practical website documentation from the app, with the setup steps most likely to matter after cloning the repository.

1. Prepare the repository

Install Git and Node.js LTS, then clone the repository. Dependencies are local to the project, so run npm install before running the CLI. 

git clone https://github.com/juliani91/project-genesis.git
cd project-genesis
npm install

The genesis script uses tsx from node_modules/.bin. You do not need a global tsx install.

2. Open the console

The local web console shows templates, registries, profiles, package metadata, enterprise policy summaries, documentation, and generated install metadata. 

npm.cmd run dev -- --hostname 127.0.0.1 --port 3000

Open http://127.0.0.1:3000 in your browser.

3. Generate a project manually

  1. Run npm.cmd run genesis.
  2. Select a registry. The local registry exposes the built-in template library.
  3. Choose manual generation.
  4. Select exactly one base template.
  5. Add compatible feature templates.
  6. Answer the wizard prompts.
  7. Choose a new output directory.
  8. Open the generated README.md and packageInstall.md.

4. Generate from a profile

  1. Run npm.cmd run genesis.
  2. Choose the profile flow.
  3. Select a profile such as web-saas-starter, api-service, or mobile-app.
  4. Review compatibility and version reports.
  5. Answer prompts and choose a new output directory.
  6. Follow the generated packageInstall.md.

5. Verify the repository

Before release work or template changes, run the project checks.

npm.cmd run verify
npm.cmd run test:template-library
npm.cmd run test:package-install
npm.cmd run test:registry-sync
npm.cmd run test:enterprise

6. Troubleshooting

  • If tsx is not recognized, run npm install from the repository root.
  • If generation fails because a directory exists, choose a new empty output directory.
  • If compatibility fails, remove the feature named in the report or choose a matching base template.
  • If two database features conflict, keep one database feature for the first generated starter.
  • If E2E tests fail, confirm the generated web app is running before running Playwright.

Install guidance

Generated projects explain their own setup.

Templates may provide packageInstall.json. During composition, Project Genesis merges those descriptors and writes a generated packageInstall.md at the project root.

System Requirements

Lists runtimes and external tools such as Node.js LTS, Python, uv, Expo, Unity Hub, Godot, Docker, or PostgreSQL.

Install Steps

Provides PowerShell-friendly commands first, with macOS and Linux alternatives where useful.

Feature Setup

Adds scoped instructions for selected features such as Playwright, Pytest, Tailwind, auth, CI, and databases.

Verify and Run

Documents verification commands and local run commands for the generated starter stack.

Governance foundation

Enterprise-ready concepts are built into the model.

Project Genesis includes organization, role, permission, audit, and policy-check foundations so template workflows can grow into governed team usage.

Organizations

Workspace metadata can group members, roles, policy checks, and audit history.

Permissions

Role permissions describe who can manage templates, registries, packages, and policy-sensitive workflows.

Audit Events

Audit summaries provide a base for traceability across publishing, sync, install, and governance actions.

Registry Sync

Registry synchronization supports repeatable package discovery and installation from configured sources.
